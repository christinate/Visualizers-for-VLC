# Shared native runtime source snapshot

`sdk/dawn` contains the production host, float analysis/capture, native UI,
module loader, codec/font services and window/presentation code. It requires
no Geiss, Terrain or MilkDrop source checkout. It uses the same Runtime.cmake
and source files as the Addon workbench; `VERSION.json` records normalized
source hashes. No binary SDK, build cache or runtime is stored in this snapshot.
Legacy API 1/2 frontends remain under runtime/native; API 4 headers are in
native. Browser sources are retained temporarily for old packaging/reference
compatibility and must not enter new native runtime payloads.

From an independent renderer repository, build the pinned dependency with
`python sdk/tools/build_dawn.py`. It records source/dependency provenance and
notices. Use the printed Dawn_DIR. On Windows also use the hash-verified SDL
bootstrap `python sdk/tools/prepare_windows_sdl.py`, then pass its SDL2_DIR.
Linux needs the documented SDL2/Qt6 development packages; Mac uses Cocoa.

```text
cmake -S sdk/dawn -B build/native-runtime -DDawn_DIR=/absolute/pinned-sdk/lib/cmake/Dawn -DSDL2_DIR=/absolute/sdl/cmake
cmake --build build/native-runtime --config Release --target VisualizerNative
```

The result is a module-only runtime, not a visualizer or complete installer.
Windows requires AMD64; Mac arm64 and Linux x86_64 are the current release
targets. Each renderer builds its own module against this shared C ABI and
Dawn revision. Standalone packages include one runtime and their own plugin;
combined packages include the runtime once and plugin-only components.

Only WebGPU C handles/operations cross the graphics-module boundary. Keep
allocation/free in the same module, track callbacks and retain borrowed
references as specified in the Addon's NATIVE-API.md (copied into dawn).
Do not statically embed another Dawn implementation in a renderer.

The host source is GPL-2.0-or-later; use its GPLv3 option for the combined
Apache-2.0 dependency distribution. Preserve original component notices and
ship corresponding source. Dependency notices are generated by the source
builder; final payload dependency/license/provenance audits remain required.
Mac return validation resumed on 2026-11-17. HDR remains Experimental/off by
default; native Windows scRGB and Mac Metal EDR include explicit SDR fallback.
Linux native HDR transport remains open. Physical HDR appearance is unverified.

## Windows native packaging

The independent Windows builder now uses explicit native file plans and does
not call the browser/Electron packager. With the pinned source-built Dawn
installation and SDL SDK prepared, run this from the renderer repository:

```powershell
python sdk/renderer-release.py --dawn-install sdk/build/dawn-install --sdl-sdk sdk/build/sdl-sdk
```

The builder configures the native runtime/module and original engine targets,
builds both Winamp bridges, verifies dependency hashes, stages notices, and
audits PE imports. NSIS must be installed; `MAKENSIS` can name its executable.
`--package-only` accepts explicit `--host-build`, `--native-build`,
`--module-build` and `--legacy-build` directories for already built artifacts.
Use `--stage-only` to inspect the payload without compiling an installer.

Output defaults to `releases/<VERSION>/windows-x86_64`. Existing staging or
output is refused; use new `--stage`/`--output` paths for additional drafts.
The portable archive contains a directly usable standalone runtime and plugin,
not installer extraction directories. Installers never download dependencies.

Standalone and Winamp share one runtime in the package installation directory.
VLC-only installs copy just the plugin into an existing native addon suite.
Native file transactions cover all selected roots, the selected bridge and
generated shortcuts. Existing destinations are refused. Uninstall verifies
ownership and hashes before removing files; user settings/additional presets
are retained. Uninstall the existing product/component before upgrading.

These are development candidates. Exact installer, real-player, dependency,
platform, stability and security checks still gate final releases. Linux/Mac
archives use the native packaging paths below.

## Linux native packaging

Linux x86_64 now has native archive builders. The addon repository's
`tools/release_native.py --build-root PATH --suite NEW-PATH --output NEW-PATH`
prepares the combined suite and three independent renderer archives. It uses
explicit native binaries/assets, one shared Dawn library and preserved
projectM SONAME symlinks. System SDL2, Qt6, OpenSSL 3 and graphics/audio
libraries are audited rather than copied from development prefixes. The VLC
integration also needs the installed VLC/Qt5 ABI. Source-built dependency
provenance and notices are included. Archives are still development drafts.

Each renderer repository can package its own checkout with
`python sdk/renderer-release-native.py`, supplying `--host-build` (the
directory with Visualizers/VisualizersCtl), `--native-build` (VisualizerNative),
`--module` and `--dawn-install`. Prism Flow additionally needs `--classic`;
MilkDrop needs `--projectm-library` pointing to its SONAME library. `--stage`
and `--output` must be fresh paths. No sibling renderer checkout is used by
this independent packaging tool.

Extract an archive and run `./install.sh` without sudo. Independent archives
default to standalone installation. `--mode vlc --prefix EXISTING-SUITE`
installs only their plugin into a native VLC addon suite. Combined archives
support all three `--without-ID` switches. Always give `./uninstall.sh` the
same `--prefix`. The uninstaller removes only components owned by that package
and checks the whole package before removing a modified file's neighbors.
User preferences and extra presets are retained; verified originals are
restored. Uninstall the existing component before upgrading.

Schema-2 install records include source hashes, file modes, relative symlink
targets and package ownership. Installed snapshots and original backups are
retained for verification/repair, so installed disk usage includes those
copies. The Linux builder does not silently create an old browser package.

## macOS arm64 native packaging

Mac archives use the same schema-2 ownership and standalone/plugin-only modes.
Each renderer can use `python sdk/renderer-release-native.py` on an arm64 Mac,
with the same module/host options plus `--sdl-library PATH` to the built
`libSDL2-2.0.0.dylib`. `--native-build` contains `VisualizerNative.app`.
MilkDrop's `--projectm-library` points to `libprojectM-4.4.dylib` and its relative
4.1.8 target. The Addon's `tools/release_native_macos.py` builds combined and
renderer archives from its explicit input layout (`--help` lists arguments).

Fresh staging copies include shared Dawn/SDL2, native modules, assets and
dependency notices. The builder removes build-machine LC_RPATH values and
relocates bundled loads to contained `@loader_path` dependencies. It checks
arm64 binaries, relative symlinks and strict local ad-hoc signatures. System
frameworks come from macOS; the VLC plugin uses the matched installed VLC
process's core. The original signed VLC app is not changed. The resulting
archives are not Developer ID signed or notarized. Intel Macs are unqualified.
Fresh compatible dependency/runtime drafts now target macOS 11.0. The audit
records minimum OS/build SDK per binary and the highest package minimum; the
signed app's LSMinimumSystemVersion must equal that minimum. Execution has
only been tested on macOS 26.6.2. Older macOS and Intel Macs still need actual
qualification; preserved earlier drafts retain their macOS 26 requirement.

Build Dawn with `python tools/build_dawn.py --macos-deployment-target 11.0`
and explicit fresh `--build`/`--install` paths plus the pinned `--source`.
In a renderer checkout use the corresponding `sdk/tools/` path. For SDL use:

```sh
python tools/build_macos_sdl.py --source-archive /PATH/SDL2-2.32.10.tar.gz \
  --source /PATH/SDL2-2.32.10 --build /FRESH/SDL-build --install /FRESH/SDL-install \
  --macos-deployment-target 11.0
```

The developer tool downloads only the locked public dependency when absent,
checks the source archive/tree and contained aliases, builds arm64 shared SDL
and writes immutable provenance under `share/vlc-visualizers/`. Use
`--record-existing` only to verify an already canonical source/build/install
with matching configuration; it still verifies all source/artifact hashes.
Packaging requires this provenance and includes it. Configure every host and
module build with `-DCMAKE_OSX_DEPLOYMENT_TARGET=11.0` and
`-DCMAKE_OSX_ARCHITECTURES=arm64` as well as the matching Dawn/SDL prefixes.
Do not reuse an SDK with a higher binary minimum under a lower archive label.

The Mac decimal parser avoids the installed libc++ floating from_chars
requirement for macOS 26. It retains finite, full-token, locale-independent
decimal/scientific input rules; integer parsing and Windows/Linux conversion
are unchanged. Native settings/palette builds and locale regression checks
pass with the 11.0 deployment target.

The Mac VLC menu integration fixture is opt-in at build time with
`VIS_NATIVE_MENU_TEST_CONTROL=ON`. Production builds must leave it OFF;
packaging rejects its command protocol marker in a VLC module. Test modules
must only be used in private copied suites, not distributed payloads.

Default combined location is `~/Library/Application Support/VLCVisualizers`;
renderer archives use their respective folder names there. Use an explicit
`--prefix` for isolated tests and the same prefix when uninstalling.
For plugin-only removal, explicitly pass the existing suite's `--prefix` even
when installation used the default suite location.
First standalone recording use requires macOS microphone approval for the production
app, independently of earlier workbench helpers. Do not edit/reset TCC to
bypass approval. Current bounded archive checks pass; final-source releases,
real capture permission and remaining player/stability checks remain gates.
